四、与源文件保持一致、可追溯

溯源链路（每条台账行都带）

  • srcFileId —— 来源文件唯一 ID，点表格首列 ⇄ 可查看来源、撤销本次导入
  • srcRel —— 来源相对路径，文件改名后自动跟随
  • srcKey —— 业务主键，决定"更新哪一行"
  • importBatch —— 批次号，整批可回退
  • srcState —— ok / missing（原件已删）

一致性由三道闸门保证

  • 批次事务：一个文件一个批次，落库失败整批回滚，不留半截数据
  • 字段级留痕：人工改过的字段记 _df，文件更新遇到它转为"冲突"待裁决，默认保留台账值
  • 对账审计：孤儿文件 / 孤儿行 / 失联行 / 重复行 四类差异，全部为 0 才算通过

验证方法与判定标准

  • 文件中心 →「数据对账」：四类差异 均为 0 即通过；任一类非 0 需先处置再入库
  • 逐条核对：表格首列 ⇄ → 弹窗列出该文件写入的全部记录与批次时间，可逐项对照原件
  • 抽样复算：抽查任意一条统计行的「检查/问题/整改」数，与源 .xlsx 对应月份逐格相符
  • 反向验证：删除一个源文件 → 其派生行应被清除、文件标记"原件缺失"；恢复后重新解析可复原
  • 幂等验证：同一批文件连续扫描两次，第二次建议条数应为 0（全部"无变化"）
